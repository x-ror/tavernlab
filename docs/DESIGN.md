# TavernLab — правила, які пережили переписування

Тут був повний проєктний документ на 2000 рядків, датований 2026-08-24:
продуктова специфікація, архітектура, схема бази, дизайн оцінювача,
план збору даних, UI/UX, роадмап і план PR-ів. Він описував Python-рушій
(`hs2/`), його HTTP-сервер (`app.py`) і половину продукту, присвячену
розбору зіграних партій (`eval/`, `capture/`, `store/`).

Нічого з того коду в дереві немає. Разом із ним скасовано й більшість
рішень, які документ обґрунтовував, — перший рядок його таблиці «Key
Decisions» звучав «Keep Python `hs2` as the only rules engine», а зараз
рушій на Rust. Тримати дві тисячі рядків обґрунтувань для коду, якого
нема, і рішень, які скасовано, — це не історія, а шум.

Повний текст лишається в історії git, якщо колись знадобиться:

```bash
git log --diff-filter=D --oneline -- docs/DESIGN.md   # знайти коміт
git show <коміт>^:docs/DESIGN.md                      # прочитати цілком
```

Пережили саме **правила**, і вони чинні досі. Решта файла — це вони.

## Чого програма не робить

| ID | Що | Чому |
|---|---|---|
| U23 | Грати за вас або «зіграй цю карту» | ToS. |
| U24 | Скрапити HSReplay.net / Untapped.gg / HSDecks заради масових реплеїв чи вінрейтів | Право + нульовий бюджет. Списки колод — можна; вони вставляються вручну. |
| U25 | Твердити «Brilliant/Best» на кшталт Chess.com Game Review | Чесність. Такий ярлик потребує оцінки, якої тут немає. |
| U26 | Повний IS-MCTS по Standard 2026 рівня KataGo | Багаторічне дослідження. |
| U27 | Платний коуч на LLM | Нульовий бюджет. |
| U28 | Радити піки Арени з чужих вінрейтів чи тір-листів | Це U24 з іншим ім'ям. Що Арені можна чесно — симуляція на вашому драфті — розібрано в `docs/ARENA_RESEARCH.md`. |

## Правовий режим

Тільки читання. **Жодного** перехоплення трафіку чи емуляції вводу — це
лишається абсолютною межею (U23: клікає завжди людина).

Читання логів (`Power.log`, `Zone.log`, `Decks.log` — та сама межа, на якій
стоять `HSTracker`/Arena Tracker), і, окремим рішенням від 2026-08-31,
**читання пам'яті власного клієнта гри, read-only** — та межа, на якій
стоять HDT/Firestone (HearthMirror): підключення до вже запущеного
Hearthstone-процесу, читання Mono-структур (`DraftManager`, дошка, рука),
ніколи запис. Причина рішення: живий трекер драфту не може радити пік, поки
трійка на екрані не проходить через жоден дозволений канал — Arena.log
її більше не пише (docs/ARENA_RESEARCH.md §7, §11), а сканувати екран
(OCR) — гірший компроміс, ніж пряме читання. Це свідомо приймає ту саму
сіру ToS-зону, в якій роками живуть великі трекери; якщо Blizzard колись
змінить позицію щодо них, змінюється й ця.

Мережевих запитів застосунок не робить узагалі. Дампи офіційного API
Blizzard, з яких зроблено корпус карт і `data/runes.json`, тягнуться
вручну командами `xtask`, ніколи самою програмою.

## Приватність

| Тема | Політика |
|---|---|
| Модель загроз | Локальний застосунок, слухає **тільки 127.0.0.1**, без автентифікації. Будь-який локальний процес може смикнути API — прийнятно для трекера, і про це сказано. |
| Прив'язка до 0.0.0.0 | **Заборонена.** |
| Логи | Можуть містити бойові теги. Читаються лише `Power.log` і `Zone.log`. |
| Сховище | Локальний SQLite. Експорт — файл користувача. Жодної телеметрії назовні. |
| Оверлей | Немає `SendInput` чи перехоплення пакетів. Читання пам'яті власного клієнта — є, але лише read-only (`memreader/`, окреме рішення від 2026-08-31, див. «Правовий режим» вище); ніколи запис, ніколи чужий процес. |
| Ілюстрації | З локального кешу, ніколи не тягнуться в момент перегляду: інакше CDN дізнавався б, яку карту ви зараз розглядаєте. |

## Чесність чисел

Три правила, які тут дорожчі за будь-яку функцію. Розгорнуто — у README,
розділ «Чесність чисел».

- **Реалізовано повністю або виключено.** Колода з нереалізованою картою
  не грається без неї; вона відхиляється з поіменним списком. Кожне
  свідоме спрощення записане в `APPROXIMATE` і читається **слабшим** за
  надруковане, ніколи сильнішим.
- **Числа не вигадуються.** Корпус старший за вікі; чого немає ні там, ні
  там, — не з'являється. Зовнішнє число називає своє джерело в тому
  рядку, де використане.
- **Кожен вимір несе свою вибірку** і свій контроль. Негативний результат
  публікується так само, як позитивний.
