# web/ — інтерфейс (React + React Spectrum)

Єдиний інтерфейс до `tavernsim serve`: живе на `/`, адреса `/app`
лишена робочою для старих закладок. Якщо `web/dist` не зібрано, сервер
віддає на `/` сторінку з інструкцією «зберіть інтерфейс», а не 404 і не
JSON.

## Чому саме так

- **Залежностей рівно чотири**: `react`, `react-dom`,
  `@adobe/react-spectrum`, `vite` (+ `@vitejs/plugin-react`). Немає
  роутера (хеш-роутинг у `src/store.jsx`), немає стейт-менеджера (один
  React-контекст), немає CSS-фреймворку (токени Spectrum +
  `src/index.css`).
- **У рантаймі Node не потрібен.** `npm run build` кладе статику в
  `web/dist`, і той самий Rust-бінарник віддає її сам.

## Робота

```bash
cd web
npm install
npm run dev      # http://localhost:5173, /api і /locales проксіюються на :8765
npm run build    # -> web/dist
```

Для `npm run dev` спершу запустіть `tavernsim serve` — дані беруться з
нього.

## Структура

```
src/
  api.js          усі HTTP-виклики + опитування задач (/api/job/{id})
  store.jsx       спільний стан: налаштування, колода, хеш-роутер
  i18n.jsx        /locales/{lang}.json із сервера + strings.js
  strings.js      рядки самого інтерфейсу (uk + en)
  format.js       відсотки, дельти, назва формату, причина відмови колоди
  classes.js      кольори, герби й арт одинадцяти класів
  meta.js         гаунтлет: назва колоди -> клас, крива мани
  components/     ui.jsx (панелі, застереження, смужки), CardTile,
                  CardCombo, HeroPortrait, ClassCrest, DeckBadge, LangPicker
  routes/         DeckLab (оцінка/покращення/муліган/суперник/тренер),
                  Gauntlet, Meta (тір-лист), Settings
```

## Рішення, які варто знати

- **Колода — один стан на весь застосунок.** Оцінка, покращення,
  муліган, суперник і нотатки тренера — вкладки однієї секції, а не п'ять
  місць, куди треба вставляти той самий деккод.
- **Ґейтів більше немає.** У попередній версії муліган і нотатки були
  закриті до «спершу проаналізуйте колоду»: телеметрія рахувалася
  хвилинами й кешувалася на диску. Rust-рушій рахує її з нуля за чверть
  секунди, тож екрани просто питають те, що їм потрібно.
- **Сервер не пише прози.** Причини в мулігані приходять кодами
  (`{k: "cheap"}`, `{k: "measured", n: 0.026}`), а фразу складає
  інтерфейс мовою, у якій він працює. Сервер бачить обидві мови й не
  може вибрати за нього.
- **Застереження — повноцінний елемент, не дрібний сірий текст.** Окремо
  від них `FieldNote` друкує, скільки колод поля справді виставлено і
  яких карт бракує решті: середнє по семи колодах, показане як середнє
  по дванадцяти, було б брехнею через замовчування.
- **Гаунтлет видно.** Кожна оцінка — це «проти оцих колод», і вкладка
  показує їх із кривою мани, повним деклистом і, коли є аналіз, вашим
  вінрейтом проти кожної. Колода лежить в адресі:
  `#/deck/gauntlet/Attack%20Druid`.
- **«Мета» — це тір-лист симулятора, і так і названо.** Мета —
  рейтинговий список із власними вінрейтами колод; гаунтлет — бенчмарк.
  Плутати їх не можна, тому це різні екрани.

## Дизайн

Темна тема **закріплена**, а не взята з системи: кожен екран тримається
на артах Hearthstone, намальованих на темному тлі, і той самий макет у
світлій темі Spectrum виглядає як помилка.

Кольори класів — це кольори класів World of Warcraft, які гравець уже
читає без підпису: рядок мага бірюзовий скрізь.

Акцент Spectrum перефарбований у латунь через його ж CSS-змінні
(`--spectrum-accent-*` у кінці `index.css`). Селектор ловить хешовані
класи по підрядку — якщо майбутній Spectrum їх перейменує, акцент тихо
стане синім; це косметика, а не поламаний екран.

## Ілюстрації

Портрети героїв і плитки карт беруться з локального кешу
(`tavernsim art-urls` — див. головний README) і **ніколи** не тягнуться
в момент перегляду: інакше CDN дізнавався б, яку карту ви зараз
розглядаєте. Без кешу нічого не ламається — `HeroPortrait` малює герб
класу (`ClassCrest.jsx`, власні SVG), а `CardTile` — рамку з назвою.

## Обмеження

Назви карт лишаються англійськими: локалізованих назв у корпусі немає.
