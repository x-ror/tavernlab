# hearthstone-sim

Симулятор Hearthstone з двома рушіями:

- **`hearthsim/` (v1)** — класичний пул карт (Basic/Classic + Naxx/GvG
  стейпли), ~206 карт, стати звірені з офіційним HearthSim/hsdata.
- **`hs2/` (v2)** — **Standard-сезон 2026** ("Escape from Violet Hold"):
  дата-шар з hearthstonejson (усі 1153 колекційні Standard-карти + токени),
  автокомпілятор простих текстів, і повністю реалізовані вручну **всі 190
  карт з 12 топ-легенд колод** дек-трекерів (деккоди декодуються нативно).

## Головна фіча: оцінка ВАШОЇ колоди

```bash
python3 evaluate.py "AAECAamACAzQngbTngb1..." --games 1000
python3 evaluate.py --file mydeck.txt --games 2000 --optimize
```

Вставляєте deckstring з гри або трекера — отримуєте:
- вінрейт проти кожної з 11 актуальних топ-легенд колод (10 000+ боїв);
- `--optimize`: рекомендовані заміни карт з виміряним приростом winrate.

Якщо в колоді є карта, чиєї механіки немає в симуляторі — програма
чесно зупиниться і назве її (політика "реалізовано повністю або
виключено", жодних мовчазних заглушок).

## Механіки рушія v2

Мана/оверлоад, втома, секрети, зброя, аури (позиційні/глобальні),
battlecry/deathrattle/тригери, combo, choose-one, outcast, spell schools,
**Death Knight (трупи)**, **Locations**, **Dormant**, **Discover**,
**квести і сайдквести**, **Start of Game** (Азаліна, Хоггер, Мug'Zee),
**Herald + солдати класів + Deathwing з Катаклізмами**, **Colossal**,
**Kindred**, **Prepare**, **Dark Gifts**, тимчасова мана, відкладені
ефекти, герой-карти, Void (Irida), 40-карт колоди (Beatrix).

Правила пост-2025 ключових слів звірені з hearthstone.wiki.gg.
Свідомі спрощення позначені `notes=` у `hs2/impls.py` (напр., Rewind =
"не перегравати", корупт-версії Dream-карт відсутні).

## Пайплайни

```bash
# Standard 2026
python3 hs2/build_data.py cards.json   # датасет з hearthstonejson
python3 run2_optimize.py 200           # 22 моїх колоди + оптимізація
python3 run2_final.py                  # матриці 10k ігор -> results2.json

# Класичний пул
python3 run_optimize.py 250 && python3 run_final.py && python3 make_report.py
```

## Відомі обмеження

- Скриптовий ШІ грає прямолінійні колоди (темпо/мідрейндж/контроль)
  значно краще за комбо-двигуни: Miracle Rogue (класика), Quest Demon
  Hunter і Soul-Immolation DH (Standard) показують занижений winrate —
  це нижня межа сили колоди, не оцінка стелі.
- Карти поза 12 топ-колодами покриті автокомпілятором лише якщо їхній
  текст повністю парситься (~240 карт пулу для оптимізатора).

## Ігровий помічник (advisor.py)

```bash
# 1) разово: інструментована статистика вашої колоди (16 500 боїв, ~5с)
python3 advisor.py stats --deck "<деккод>" --games 1500

# 2) муліган проти конкретного класу — з виміряним впливом і поясненням
python3 advisor.py mull --deck "<деккод>" --opp druid \
    --hand "Vulcanos;Frostbolt;Fireball"

# 3) читання суперника: що він, ймовірно, грає і які загрози чекати
python3 advisor.py predict --opp rogue --seen "Preparation;Deja Vu"

# 4) журнал самопокращення (дописує coach_log.md)
python3 advisor.py coach --deck "<деккод>"
```

`watcher.py --log <Power.log>` — імпорт ваших реальних ігор (див.
«Огляд гри» нижче).

Застереження: муліган-дельти — кореляційні оцінки з симуляцій зі
скриптовим ШІ, а не каузальний ефект вашого рішення; читайте їх як
орієнтир, підкріплений поясненням.

## Локальний додаток (Таверна-Лаб)

```bash
python3 app.py          # відкриє браузер на http://127.0.0.1:8765
./build_app.sh          # збірка в один файл (PyInstaller) -> dist/TavernLab
```

Вкладки: Ігри, Огляд, Імпорт, Оцінка колоди (+пошук покращень), Муліган,
Суперник, Тренер, Налаштування. Інтерфейс двомовний (en + uk):
`locales/en.json` / `locales/uk.json`, мова береться з системи й
перемикається в Налаштуваннях.

Для Windows: запустіть build_app.sh у Git Bash або виконайте команду
pyinstaller з нього вручну (роздільник даних `;`). Ціль збірки —
**CPython 3.11**; репозиторій компілюється й під 3.14, але onefile треба
збирати на 3.11 і перевіряти на **справжній Windows 11**, не під Wine.

## Огляд гри (post-game review)

```bash
pip install -r requirements.txt
python3 watcher.py --log "<...>/Logs/Hearthstone_.../Power.log"
python3 watcher.py --last-session --logs-dir "<...>/Logs"
python3 app.py            # вкладка «Ігри» -> «Огляд»
```

Що відбувається:

1. **Імпорт.** `capture/hslog_import.py` розбирає Power.log по **Packet
   Tree** бібліотеки `hslog` (обхід у глибину: `BLOCK_START` -> вкладені
   пакети -> `BLOCK_END`). `EntityTreeExporter` **не** використовується:
   він повертає лише *кінцевий* стан сутностей, тож дошки по ходах у ньому
   немає. Один потік логера на файл (PowerTaskList, інакше GameState) —
   інакше дерево подвоюється.
2. **Сховище.** `store/` — SQLite у WAL з **одним потоком-письменником**
   (`tavernlab.sqlite`). Події append-only; зріз Power.log лежить у
   `games.raw_power` (gzip). `games.jsonl` більше не пишеться —
   при першому запуску старі рядки переносяться як `status='partial'`
   (без подій, тож без огляду).
3. **Реконструкція.** `eval/visible.py` згортає події у `VisibleState` —
   те, що лог справді показує. Це **не** `hs2.Game`.
4. **Оцінка.** `eval/mapper.py` накладає стати на `Game.__init__` (без
   `start()`, суперник — реалізовані карти *його* класу), `hs2/lethal.py`
   шукає летал, `eval/ledger.py` рахує невитрачену ману й невикористані
   атаки, `eval/review.py` збирає Review JSON.

Нові маршрути (усі GET читаються через `getJSON()` у веб-інтерфейсі —
старий `api()` вміє лише POST):

```
GET  /api/games?limit=&class=&result=      GET  /api/games/{id}
GET  /api/games/{id}/review                GET  /api/games/{id}/replay
GET  /api/games/{id}/events?from_seq=      GET  /api/labels
GET  /api/settings                         GET  /locales/{lang}.json
POST /api/import/log {path}                POST /api/import/last_session
POST /api/games/{id}/analyze               POST /api/settings
POST /api/cards {ids:[...]}                POST /api/cardnames {all:true}
```

### Чесність оцінок

MVP показує рівно три мітки: **пропущений летал**, **зіграний летал**
(тихо) і **нотатки** леджера. Mistake / Blunder / Best / Brilliant /
Lucky / Unlucky у легенді сірі — вони вимагають `search_ok`
(повний граф тригерів), а в цій збірці `search_ok = 0` завжди.

Графік шансу перемоги **завжди штрихований**: це логістика на 8 ознаках
дошки + bias (9 ваг), 66.7% на снапшотах симулятора, не каліброваних на
людських іграх. Вона **не** ранжує ходи, і жоден хід не позначається
червоним через ΔWP.

`lethal_ok` описує **позицію**, а не те, чи ми там шукали: він означає
«накладка статів на цю позицію коректна». Окреме поле `lethal_checked`
каже, чи солвер справді відпрацював на цьому плаї — глибокий пошук має
бюджет і запускається двічі за наш хід, а не на кожному плаї. Без цієї
різниці плай, який ніхто не перевіряв, виглядав би як «перевірено, леталу
не було».

Пропущений летал публікується лише коли `lethal_ok` (стати розібралися) —
нереалізована карта може лише *додати* урону, тож хибний позитив вона не
створює. Коли в руці є нереалізовані карти, «леталу не було» означає
«невідомо», а не «доведено, що немає».

Точність пошуку леталу міряється, а не декларується:
`tests/test_lethal_precision.py` генерує 1200 випадкових позицій на режим,
виконує кожен знайдений план на клоні й перевіряє, що суперник справді
помер. Поточний результат — **0 хибних позитивів** з 868 знайдених леталів
(2400 позицій). Повноту (recall) не заявляємо: для неї потрібен набір
головоломок, розмічений чимось іншим, ніж цей самий солвер (v1, §3.8).

Стратегічні підказки (`eval/taggers.py`) виходять лише з перевірюваними
числами: «ви — beatdown, ви вбиваєте за 2 ходи при 11 урону в обличчя».
Якщо жоден годинник не швидший за 6 ходів або різниця менша за 2 ходи —
тег мовчить. Неправильний стратегічний тег гірший за жоден.

### Спостережуваність і відновлення

`$WORKDIR/tavernlab.log` (ротація 2 МБ × 3). HTTP-доступ пишеться лише з
`TAVERNLAB_DEBUG=1` — інтерфейс опитує задачі кожні 700 мс і без прапорця
завалив би файл. `GET /api/metrics` віддає локальні лічильники: скільки
ігор імпортовано, скільки оглядів, середній час огляду, частка рішень з
`lethal_ok` і з `search_ok` (останнє в цій збірці має читатися як 0.0 —
воно **міряється**, а не припускається). Нічого нікуди не надсилається.

`POST /api/games/{id}/reparse` перерозбирає збережений зріз Power.log
(`games.raw_power`) у **нове покоління**. Це сенс того, що зріз узагалі
зберігається: коли імпортер виправлять, стару гру можна перечитати, навіть
якщо оригінального лога вже немає. Читання автоматично перемикаються на
нове покоління — правило `MAX(parse_generation)` (§2.2).

### Правовий режим

Тільки читання офіційних логів. Ані читання памʼяті, ані перехоплення
трафіку, ані емуляції вводу — `python3 tools_tos_grep.py` падає, якщо
щось із цього зʼявиться в репозиторії. Живі підказки під час гри —
опційні, вимкнені за замовчуванням; типовий режим — розбір після гри.

## Нові модулі (v2.1)

- `eval/taggers.py` — beatdown-годинники та муліган-чеклист «6+ на ходу»;
  обидва мовчать, коли доказів мало.
- `eval/classify.py` — єдине місце, де вирішується, що можна показати;
  легенда з сірими мітками береться звідти ж (`GET /api/labels`).
- `hs2/actions.py` — `Action` на стабільних **eid**, `legal_actions()`
  (з прапорцем `actions_complete`) і `apply(..., forced_picks=)`, щоб
  вкладені Discover не перекидалися заново під час повтору.
- `hs2/effects.py` — `PendingListen` / `PendingTurnStart` + реєстр
  `HANDLERS`. Раніше `Player.listeners` тримав **замикання** над живими
  обʼєктами, і клон продовжував спрацьовувати на *оригіналі*.
- `Game.clone()` — копія для пошуку. Джерело істини — `_by_eid`, а не
  списки зон: інакше карти поза зонами (Void в Irida, overflow у
  Godfrey) залишилися б спільними з оригіналом.
- `hs2/lethal.py` — точний пошук леталу поточного ходу (атаки з розчисткою
  таунтів перебором, віндфʼюрі, берн-спели через mana-knapsack, геройські
  сили). Вбудований у ШІ. `deep=True` (тільки для огляду) додає
  play-then-lethal на один пляй і вимірює невідому геройську силу на
  клоні; обмежений пошук таунтів тепер повертає план з `approx=True`,
  а не мовчазний `None`.
- `hs2/winprob.py` — шанс перемоги в моменті: логістична модель, натренована
  на 141k снапшотів симуляцій (точність 66.7% на відкладених даних).
  API: `POST /api/winprob {"hp_diff":…, "board_atk_diff":…, "my_turn":…}`.
- `live.py --log Power.log --deck "<код>" --name Нік` — LIVE-помічник:
  муліган-поради на старті, після кожної карти суперника — прогноз колоди
  і загрози. (Регекс-тейл; повноцінний live-режим — v1, PR 6.)
  `live.build_sim_state` **виведено з обігу**: він викликав `start()`,
  жорстко ставив `turn = 10` і роздавав вашу колоду обом гравцям.
  Замість нього — `eval.mapper.build_overlay`.
- `update_meta.py --add "Назва" "AAECA…"` — оновлення гаунтлета новими
  колодами з трекерів + звіт про нереалізовані карти (`--check`).
