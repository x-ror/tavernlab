# TavernLab

Локальна лабораторія колод Hearthstone: симулятор правил на Rust і
веб-інтерфейс до нього. Один бінарник віддає і статику, і API; нічого
нікуди не надсилається.

```bash
cd web && npm install && npm run build      # інтерфейс, один раз
cargo build --release --manifest-path tavernlab-sim/Cargo.toml
tavernlab-sim/target/release/tavernsim serve   # http://127.0.0.1:8765
```

Без зібраного `web/dist` сервер віддає сторінку з цією ж інструкцією, а
API вже працює.

## Що вона рахує

Вставляєте деккод із гри або з сайта колод — і отримуєте:

| Вкладка | Питання | Звідки відповідь |
|---|---|---|
| **Оцінка** | скільки ваша колода бере проти поля | 1000 боїв проти кожної колоди гаунтлета |
| **Покращення** | яку карту замінити | пошук по одній заміні з **перевимірюванням** переможця |
| **Муліган** | що лишати в стартовій руці | інструментовані симуляції: вінрейт ігор, де карта була в руці |
| **Суперник** | у що він, ймовірно, грає | збіг побачених карт зі списками гаунтлета |
| **Нотатки тренера** | які карти тягнуть колоду вниз | той самий інструментований прогін, згорнутий по картах |
| **Гаунтлет** | проти чого вас узагалі міряють | самі списки, з кодами й кривою мани |
| **Мета** | тір-лист симулятора | гаунтлет грає сам проти себе |

Рушій дає ~23 000 ігор/с на одному ядрі й ~90 000 на чотирьох
(`tavernsim bench`), тож жоден із цих екранів не треба «спершу
прогріти»: муліган-порада рахується з нуля за чверть секунди.

## Гаунтлет: що виставляється, а що ні

**Гаунтлет** — фіксований набір колод, з якими симулятор порівнює вашу.
Це джерело вашого відсотка, а не рейтинг.

Колоду, у якій є хоч одна нереалізована карта, симулятор **не виставляє
взагалі**: викинути карту означало б зсунути вінрейт на невідому
величину й видати це за вимір. Такі колоди лишаються у списку, позначені
іменем карти, якої бракує, і кожна відповідь API несе поля
`field_decks` / `field_played` / `field_skipped`, а інтерфейс друкує їх
під числом.

Станом на цю збірку:

| формат | колод у гаунтлеті | виставляється |
|---|---|---|
| Standard | 12 справжніх топ-легенд колод | 7 |
| Wild | 11 згенерованих baseline-колод | 11 |

П'ять Standard-колод тримають чотири карти: `Deathwing, Worldbreaker`
(три колоди), `Lunarwing Messenger`, `Soul Immolation`. Реалізуйте їх у
`tavernlab-sim/core/src/cards/behaviour.rs` — і поле відновиться саме.

Wild-гаунтлет — **не мета**: правовий режим виключає збір даних із
HSReplay/Untapped, тож джерела справжньої Wild-мети немає. Замість неї
`cargo run -p xtask -- wild-gauntlet` збирає по колоді на клас із
реалізованого Wild-пулу; провенанс лежить у полі `source` кожної колоди.
Перегенеровувати треба щоразу, коли змінюється реалізований пул.

**Мета** (вкладка з тір-листом) — це гаунтлет проти самого себе: кожна
колода проти кожної, дзеркала виключені, тір — смуга середнього
вінрейту. Це **не** рейтингова таблиця: вінрейтів із HSReplay тут не
буде ніколи (`docs/DESIGN.md`, U24). Разом із таблицею друкується
похибка: на 50 боях на пару це ±14 в.п. — ширше за самі смуги тірів, і
таблиця про це прямо каже.

## Скільки покрито

```
Standard: 372 з 1210 колодних карт (30.7%) — 26 з них наближені
Wild:     893 з 7017 (12.7%)             — 27 наближені
```

`tavernsim coverage` друкує це по класах і поіменно перелічує кожне
свідоме спрощення. Політика «реалізовано повністю або виключено»:
колода з нереалізованою картою відхиляється з поіменним списком, а не
грається без неї.

`tavernsim backlog <class>` друкує, яких саме карт бракує класу, з
текстом і вартістю — робочий список на наступний захід.

## Чесність чисел

- **Парні вибірки.** Кожен кандидат у оптимізаторі грає ті самі сіди, що
  й база. Дві колоди, у яких спільні 29 карт із 30, різняться значно
  менше за шум двох незалежних вибірок.
- **Прокляття переможця.** Найкраща з 24 зашумлених спроб завищена вже
  тим, що її обрали максимумом. Тому лідер кожного раунду
  **перемірюється** на вчетверо більшій і геть іншій вибірці, і в звіт
  іде саме друге число. Python-версія цього не робила й мусила
  попереджати, що друкована цифра завищена.
- **Хто ходить першим — чергується, а не кидається.** Монетка — велике
  й цілком уникне джерело шуму.
- **Порогів на віру немає.** Карта потрапляє в поради мулігану від 30
  появ у матчапі, у нотатки тренера — від 100; нижче цього API віддає
  `null`, а не число.

Застереження, які інтерфейс друкує поруч із кожним екраном, — не
дрібний шрифт: ШІ скриптовий, тож комбо-колоди він недооцінює, і
дельти — кореляційні оцінки із симуляцій, а не каузальний ефект вашого
рішення.

## Формати

Формат береться з самого деккоду (`1` = Wild, `2` = Standard). Корпус
один на обидва: кожна карта несе біти форматів, тож перемикання — це
перевірка біта, а не другий корпус. Twist і знятий Classic не мають
пулу, який можна вивести з кодів сетів: такий деккод резолвиться, але
оцінюється як Standard, і задача каже про це в лозі.

Вставляйте деккод як є — цілим блоком із коментарями, як його віддають
сайти колод. Код знаходиться **розбором** рядків-кандидатів, а не за
формою: у блоці є й інші base64-подібні слова, і перевірка довжини
радісно вибрала б одне з них. Назву з рядка `### Zee Shaman` інтерфейс
підхоплює й показує; зберігається завжди голий код.

## Де лежать ваші дані

`settings.json` і кеш тір-листа — у теці даних користувача, а не поруч
із програмою:

| ОС | тека |
|---|---|
| Windows | `%LOCALAPPDATA%\TavernLab` |
| macOS | `~/Library/Application Support/TavernLab` |
| Linux | `$XDG_DATA_HOME/TavernLab` (типово `~/.local/share/TavernLab`) |

Перевизначається змінною `TAVERNLAB_HOME`. Дані самої програми
(`data/`, `locales/`, `web/dist`) шукаються від робочої теки й від
бінарника вгору; `TAVERNLAB_ROOT` має пріоритет. Порт — `TAVERNLAB_PORT`
або перший аргумент `serve`.

## Ілюстрації

Портрети героїв і плитки карт — окремо й один раз. Нічого в цьому
воркспейсі не вміє HTTPS (це коштувало б TLS-залежності, а сенс правила
«нуль залежностей» саме в тому, що бінарник не може випадково піти в
мережу), тож програма друкує список адрес, а ви завантажуєте їх чим
завгодно:

```bash
tavernsim art-urls --heroes | while IFS=$'\t' read -r url dest; do
    mkdir -p "$(dirname "$dest")" && curl -sSfo "$dest" "$url"
done
```

Без `--heroes` друкуються ще й плитки всіх реалізованих карт (~36 МБ).
Кеш віддається з диска через `GET /api/art/{hero|tile}/{id}`; у рантаймі
мережі не буває — лінива підвантажка розповідала б CDN, яку карту ви
зараз дивитесь. Без кешу інтерфейс малює власні герби класів.

## API

Усе під `/api`, усе локальне. `GET` — читання, `POST` — усе, що бере
деккод; дві довгі задачі віддають `job` і опитуються.

```
GET  /api/settings           GET  /api/metrics        GET  /api/job/{id}
GET  /api/tiers?format=      GET  /api/art/{kind}/{id}
GET  /locales/{lang}.json
POST /api/resolve {code}     POST /api/analyze {code, games}   → job
POST /api/optimize {code}    → job                             POST /api/tiers {format, games} → job
POST /api/mull {code, opp, hand}     POST /api/coach {code}
POST /api/predict {opp, seen, format}
POST /api/meta {format}      POST /api/cardnames {all, cls}
POST /api/settings {…}
```

Сервер відповідає лише на loopback-`Host`: сторінка з інтернету, яка
наведе своє ім'я на 127.0.0.1, інакше могла б говорити з цим API руками
вашого ж браузера.

## CLI

```text
tavernsim serve [port]              застосунок: інтерфейс + API
tavernsim bench [games] [threads]   пропускна здатність на дзеркалі
tavernsim matrix [games]            кожен клас проти кожного
tavernsim demo [seed]               одна гра, хід за ходом
tavernsim coverage                  скільки пулу реалізовано
tavernsim gauntlet [path]           скільки справжніх списків резолвиться
tavernsim backlog <class>           яких саме карт бракує класу
tavernsim art-urls [--heroes]       звідки взяти кеш ілюстрацій
```

## Структура

```
tavernlab-sim/     Rust-воркспейс
  core/            рушій правил: стан гри, карти, ШІ, батчі,
                   деккоди, телеметрія, оптимізатор, тіри
  cli/             бінарник `tavernsim`, зокрема HTTP-сервер (serve/)
  json/            читач і письменник JSON без залежностей
  xtask/           генератор карткової таблиці й Wild-гаунтлета
data/              корпуси карт і гаунтлети
locales/           переклади (en, uk)
web/               React + Adobe React Spectrum, Vite
docs/              DESIGN.md — історія рішень
```

Залежностей у продакшн-збірці нема жодної — ані в Rust, ані на рантаймі:
ні serde, ні HTTP-фреймворку, ні SQLite. Карткова таблиця вкомпільована
в бінарник як згенерований Rust (`cargo run -p xtask -- cards`), а не
парситься зі старту.

## Тести

```bash
cargo test --manifest-path tavernlab-sim/Cargo.toml
```

Головні гейти: по тесту на карту (`core/tests/cards.rs`), детермінізм
батчів (той самий результат на 1 і на 4 потоках), відповідність
телеметрії звичайному прогону на тих самих сідах, легальність колод, які
видає оптимізатор, декодер деккодів проти справжнього коду з сайта,
захист від виходу за корінь статики і перевірка `Host`.

## Правовий режим

Тільки читання офіційних даних, жодного читання пам'яті, перехоплення
трафіку чи емуляції вводу. Мережевих запитів програма не робить взагалі:
`/api/metrics` — це локальні лічильники, і вони нікуди не йдуть.

## Що пішло разом із Python

Тут був другий рушій на Python і HTTP-сервер до нього (`app.py`, `hs2/`,
`eval/`, `capture/`, `store/`). Його видалено; разом із ним пішли
функції, яких у Rust-ядрі немає:

- **Імпорт `Power.log` і «Огляд гри»** — список ваших ігор, реплей,
  мітки пропущеного леталу, леджер невитраченої мани, графік шансу
  перемоги, SQLite-історія. Розбір лога тримався на бібліотеці `hslog`,
  а мітки — на солвері леталу й логістичній моделі, яких у Rust ще
  немає. Розділи «Тренер», «Ігри» та «Імпорт» прибрано з інтерфейсу
  замість того, щоб лишити порожні вкладки.
- **Перезбирання корпусу карт** (`scripts/build_cards.py` +
  `hs2/build_data.py`): злиття живого card-library API Blizzard із
  `CardDefs.xml`. `data/*_cards.json` у репозиторії — результат
  останнього такого прогону; наступна ротація Standard потребує, щоб цей
  пайплайн хтось переписав (історія в git його зберігає).
- **Завантажувач ілюстрацій** — замінений на `tavernsim art-urls`
  (див. вище).

Усе інше портовано: деккоди, оцінка проти гаунтлета, оптимізатор,
телеметрія, муліган, читання суперника, тір-лист, налаштування, локалі,
статика.
